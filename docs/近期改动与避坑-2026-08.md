## 1. 数据与入口分层（先分清）

| 入口 | 数据来源 | 是否进日记/值得细看 | 关键文件 |
|------|----------|---------------------|----------|
| 首页「出国旅行 · 示例」 | 本地常量 | **否** | `homeDemos.ts` |

**重点：**

- 旅行示例（药盒/景点/酒店/航班 Unsplash）**不要**塞进日记 Demo，两套互不影响。
- 日记与「值得细看」共用同一 `memories` 列表；要两边都有默认内容，必须进 Memory 形态数据（或客户端合并 mock Memory）。
- 排序：`withDiaryDemoMemories` 合并后按 `created_at` **降序**（最新在前）。

## 4. 后端：药品说明 / Schema / 看图

### 4.1 Zod 数组字段

LLM 对「看不清」常返回 `null`。`.default([])` **只吃 undefined，不吃 null** → 会 500「洞察结构校验失败」。

已用 `arrayField` / `stringArrayField`（`null` → `[]`）。扩展 schema 时**新数组字段务必同样处理**。

### 4.2 药品说明必须看图

专项 `qualityMode` 默认走「caption + 纯文本 LLM」。  
**药盒/菜单**若只靠 caption，用法用量/功效极易空。

`vlm.ts` 已对 `med_label`、`menu_translator` **强制 vision**（与 `palm_reader` 类似）。  
文案兜底：`medSanitize.ts`（空字段补「未清晰显示…」提示）。

### 4.3 食识拍内容曾「变少」的真因

- **不是** schema 删字段了；是 `FoodScanInsightSections` 只渲染了营养环 / diet_summary / tips / allergens。
- 已补回展示：`subtitle`、`visible_clues`（盘中食材）、`flavor_notes`、`context.practical` / `cultural`、`nearby_picks`。
- Prompt 要求完整输出上述关键字段；改 UI 时先对照 schema，再对照组件是否渲染。

## 5. 线上 vs 本地（最高频坑）

当前 App `.env` 常指向：

```text
EXPO_PUBLIC_API_URL=https://vision-agent-api.onrender.com
```

| 现象 | 原因 | 处理 |
|------|------|------|
| 本地改了 API，手机行为不变 | 打的是线上 | 部署 Render，或改 `.env` 为本机 IP 后 Reload |
| 药品没有用法/功效 | 线上未部署强制看图 + 新字段 | 部署 `vision-agent-api` |
| Demo 模式台灯示例 | 未配 LLM | `/health` 看 `demo_mode` |

改 `.env` 后必须 **Reload Metro**，否则仍用旧 URL。

## 6. 避坑 Checklist（本阶段补充）

- [ ] **两套 Demo 别混**：`homeDemos` ≠ `diaryDemos`
- [ ] **schema 数组**：LLM 的 `null` 要用 preprocess，别只靠 `.default([])`
- [ ] **文字包装类 Agent**（药盒、菜单、登机牌）：优先看图，别只喂 caption
- [ ] **有字段 ≠ 用户看得见**：改 prompt/schema 后同步改 Insight Sections
- [ ] **浅色专项页**：`theme.light` + 独立组件；别再塞进深色 `InsightCard` 里硬改
- [ ] **列表预览清晰度**：大卡用 `image_url`，别用过小 thumb
- [ ] **示例 Memory**：`demo-` / `demo-diary-` id 禁止追问、删除要拦
- [ ] **部署意识**：连 onrender 时，本地 API 改动不等于线上生效
